# x_kcorr: полный round-trip через нормированное пространство (R32)

## Проблема

При калибровке с разными масштабами по осям (`x_kcorr != 1`) поправка
считалась, сохранялась в пресет и показывалась на лейбле, но **никуда
дальше не применялась**. Вся геометрия зон и все метрики шли по одному
скаляру `pxl2sm` (это Y-масштаб) с изотропным `bwdist`. На анизотропном
кадре кольца/зоны получались физически неверными (правильные по Y, но
ошибочные по X ровно в `x_kcorr` раз), объект-«круг» подгонялся как
пиксельный круг вместо физического эллипса, а скорости/дистанции меряли
X и Y в одном масштабе.

## Что сделано

Введено нормированное (изотропное, в см) пространство: X растягивается на
`x_kcorr`, Y без изменений -> 1 px = один и тот же см по обеим осям. Всё
геометрическое строится там, потом обратная трансформация для отрисовки/
хранения, чтобы легло на кадр видео. Примитивы: `+sphynx/+geom/`
(`toNormPoints`/`fromNormPoints`, `toNormMask`/`fromNormMask`,
`buildZonesInNorm`, `hypotKcorr`).

Round-trip заведён в 5 областях:

1. **Стратегии зон арены** (`computeZonesFromUI` в CreatePresetApp):
   маска арены + угловые точки + вершины полигона нормируются, зоны
   строятся в норм-пространстве, маски возвращаются в пиксели.
2. **Кольца вокруг объектов** (`buildObjectZones`, параметр `XKcorr`):
   инфляция `ZoneWidthCm` считается в норм-пространстве.
3. **Интерполяция объекта/арены кругом** (`readArenaGeometry`,
   `readObjects`, параметр `XKcorr`): Circle и O-maze фитятся в
   норм-пространстве -> в пиксели выходит корректный эллипс.
4. **Скорость и дистанция** (`computeVelocity`, `velocityJumpFilter`,
   параметр `XKcorr`): X-компонента смещения растягивается на `x_kcorr`.
5. **Дистанции в актах** (`rear`, `applyAct` через `ctx.xKcorr`;
   протянуто в `analyzeSession` и `makeActContext` из `Options.x_kcorr`).

`x_kcorr == 1` везде — точный no-op (identity), поэтому все старые тесты
и пресеты без анизотропии не меняются.

## Тесты

Новые unit-тесты: geomNormalizedSpace (7), buildObjectZonesKcorr (3),
buildZonesInNorm (2), readArenaGeometryKcorr (2), hypotKcorr (5),
computeVelocityKcorr (3). Полная суита (fast+golden): **0 failed**,
3 incomplete (пре-существующие readFrameAt, зависят от видео-ридера).

## На вычитку (нюансы, не баги)

- **Circle drag vs points.** Для геометрии Circle фит теперь всегда идёт
  в норм-пространстве. Для режима «отметить точки по контуру» это ровно
  то, что нужно (объект физически круглый). Для режима «перетащить круг»
  при `x_kcorr != 1` нарисованный пиксельный круг будет
  интерпретирован как физический круг (в пиксели вернётся эллипс). Если
  для drag-режима нужно сохранять буквальный пиксельный круг — скажи,
  разведу два режима.
- **Порядок операций.** Fit использует `x_kcorr` на момент рисования;
  gate `requireCalibration` уже требует калибровку до зон. Если
  откалибровать ПОСЛЕ разметки — старые border'ы не перефитятся
  (refitAllMasks только перезаливает маску из существующего border).
  Рекомендуемый порядок: калибровка -> арена/объекты -> зоны.
- **saveSessionPlots** (визуализация траектории в см) оставлен как есть:
  `xCm = X/pxlPerCm` изотропно, но и кадр, и траектория рисуются в одном
  масштабе, так что оверлей согласован. Для «истинных см» по X можно
  домножить на `x_kcorr` — отдельная мелкая правка, если понадобится.

## Проверить на реальном анизотропном файле

Открыть CreatePreset, откалибровать 4 точками так, чтобы X/Y разошлись
> 3% (лейбл покажет `kcorr != 1.000`), разметить арену/объекты, в пункте
5 построить зоны. Кольца должны быть физически равномерными (в пикселях
уже, где масштаб выше), объект-круг лечь эллипсом ровно по видимому
объекту.
