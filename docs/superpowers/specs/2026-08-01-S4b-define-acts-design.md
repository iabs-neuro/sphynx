## 1. Место в S4

Второй срез из пяти (порядок задан в S4a). Наполняет вкладку **Define Acts** и добавляет
этограмму, которой не было в S1.

**Входит:** простые акты (часть тела в зоне + пороги скорости + пост-фильтры), акты-семейства
(привязка к классу зон), библиотека актов в JSON, слияние с актами парадигмы, предпросмотр
на загруженной сессии, этограмма.

**Не входит:**
- редактор деревьев-выражений (OR/AND/EXCLUDE/последовательности) — свой срез, у него
  принципиально другой UI, и делать его вслепую до обкатки простого конструктора рано;
- конструктор именованных метрик — опирается на реестр метрик и логичнее рядом с Make Output;
- чтение старых `.mat`-библиотек актов — этот формат в Python не портирован. Конвертер
  имеет смысл писать, только если такие файлы реально есть; пока не пишем.

## 2. Формат библиотеки

JSON, теми же правилами, что у парадигм (`sphynx.paradigms.io`): версия схемы обязательна,
неизвестные поля отвергаются с ошибкой (опечатка в правленом руками файле не должна тихо
терять акт), нефинитные числа кодируются явно, запись через временный файл.

Модуль `sphynx.acts.library_io`: `library_to_dict`, `library_from_dict`, `save_library`,
`load_library`. Библиотека — это `{"schema_version": 1, "acts": [...], "families": [...]}`.

## 3. Слияние с парадигмой

Порядок вычисления: встроенные скоростные акты (rest/walk/locomotion/freezing/rear) ->
акты и семейства парадигмы -> акты и семейства библиотеки.

**Одноимённый акт из библиотеки перекрывает** акт парадигмы (так же вёл себя MATLAB).
Перекрытие НЕ тихое: оно попадает в отчёт валидации как запись уровня `info` с кодом
`act_overridden`, и панель варнингов её показывает. Пользователь всегда видит, что
посчитано не то, что объявила парадигма.

Слияние живёт в `sphynx.pipeline.paradigm_bridge`, а не в GUI, поэтому работает и из CLI:
`apply_paradigm(result, paradigm, library=None)`.

## 4. Вкладка: две панели

**Слева — список актов.** Для каждого показан источник: `builtin` / `paradigm` / `library`.
Перекрытый акт парадигмы отображается зачёркнутым с пометкой, каким актом он перекрыт.

**Справа — редактор выбранного акта:**
- тип привязки: одна зона | класс зон (семейство);
- зона или класс — выпадающий список, собранный из зон **загруженного пресета** (с их
  классами), а не из свободного текста: акт не должен ссылаться на несуществующую зону;
- часть тела — выпадающий список частей из загруженной сессии;
- пороги скорости min/max;
- пост-фильтры: минимальная длительность, склейка пауз, медианное окно.

**Цепочка замен частей тела (`fallback`) пользователю НЕ редактируется.** Это решение о
валидности измерения, а не настройка: произвольная подстановка — ровно та тихая подмена,
которую запрещает §10. Редактор задаёт только `body_part`, из которой движок выводит
`required_parts = [выбранная часть]`; `fallback` остаётся пустым, поэтому пропавшая часть
даёт честную деградацию с пометкой. Цепочки будут прописаны централизованно позже.

Кнопки: создать, дублировать, удалить, сохранить библиотеку, загрузить библиотеку.

## 5. Предпросмотр

Кнопка **Preview** считает выбранный акт на сессии, уже загруженной во вкладке Analyze
(`AppState.result`), и показывает процент, число эпизодов, суммарную длительность и
этограмму этого акта.

Предпросмотр считает **ровно по тем кадрам, которые загружены**, и подписывает диапазон
(«preview over 3000 of 18006 frames»). Тихо пересчитывать всю сессию нельзя: цифры
разошлись бы с таблицей в Analyze, и никто бы не понял почему. Если сессия не загружена,
кнопка сообщает об этом, а не возвращает пустой результат.

## 6. Этограмма

Добавляется в `sphynx.plot.etogram` как обычный плот: по строке на акт, горизонтальные
полосы эпизодов вдоль времени. Используется дважды:
- в Define Acts — одна строка для предпросматриваемого акта;
- во вкладке Analyze — все акты сессии; становится пятым графиком, сетка 2x2 превращается
  в 2x3 (этограмма шире прочих, поэтому занимает нижнюю строку целиком).

## 7. Тестирование

- Движок: round-trip библиотеки через JSON (включая отказ на неизвестном поле и версии),
  слияние с парадигмой, перекрытие одноимённого акта с записью в отчёт, вывод
  `required_parts` из выбранной части тела.
- GUI (`pytest-qt`, headless): список наполняется из трёх источников с правильными метками,
  редактор читает и пишет модель акта в обе стороны, предпросмотр без загруженной сессии
  сообщает об этом, предпросмотр подписывает диапазон кадров, сохранение/загрузка
  библиотеки через диалог.
- Этограмма: рисуется для нескольких актов, не падает на акте без единого эпизода.

## 8. Критерии готовности

- Во вкладке Define Acts можно создать акт «нос в зоне класса `object_area`», сохранить
  библиотеку, увидеть предпросмотр с этограммой.
- Загруженная библиотека участвует в анализе: её акты появляются в таблице Analyze, а
  перекрытие акта парадигмы видно в панели варнингов.
- Этограмма показывается во вкладке Analyze для всех актов сессии.
- Полная сюита зелёная.
