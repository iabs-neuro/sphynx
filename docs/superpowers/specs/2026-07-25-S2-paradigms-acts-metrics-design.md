## 1. Корневая проблема

Акты и метрики — разные уровни (per-frame сигнал vs per-session скаляр), не «перемешаны».
Каша в Barnes происходила из-за: (а) отсутствия слоя Events; (б) того, что роли зон и их
наследование в акты нигде не выражены — отсюда в MATLAB захардкоженные `order_barnes`,
`NumObjects=19`, семейства через строковый парсинг имён. S2 выражает роли декларативно и
разворачивает семейства по фактической геометрии.

## 2. Принятые решения брейнсторма (2026-07-25)

1. **Деградация актов по частям тела — явная fallback-цепочка на акт.** Каждый акт
   декларирует `required_parts` + собственную `fallback`-карту (`{nose:[snout],
   head_center:[neck]}`). Пропажа части без fallback -> варнинг + честный NaN + флаг
   `degraded`; НИКОГДА тихая подмена (это баг R31#4). Дублирование между актами снимается
   библиотекой стандартных цепочек, но декларацию держит сам акт.
2. **Composition комплексных актов — AST (дерево-выражение).** Узлы `Or/And/Exclude/
   Sequence(delays)`, листья — zone-act / speed-act / special / ссылка на именованный акт.
   Заменяет плоскую `components+operation` модель S1.
3. **Граница metadata/эксперимент.** Парадигма несёт config-дефолты + правила валидации.
   Metadata (mouse/group/line/day/trial) остаётся per-session данными (уже в `run_batch`
   specs / `build_super_table`). Полноценный менеджер экспериментов/проектов (парсинг
   директорий, накопление, UI) -> S4.

## 3. Архитектура (8 слоёв, снизу вверх)

### Слой 1. Роли зон (геометрия — единственный источник правды)

`Zone` (сейчас: name, type, maskfilled) расширяется декларативными полями:

```
Zone:
  name: str
  zone_class: "hole" | "object" | "wall" | "corner" | "arena"
  maskfilled: ndarray[bool]
  roles: { is_target: bool, tags: list[str] }
  index: int | None          # порядковый в своём классе (для семейств)
  angle: float | None         # угол центроида зоны относительно центра арены, рад
```

- Роли ставятся ОДИН раз при рисовании масок (в пресете). Нейтральная лунка =
  `zone_class=="hole"` без `is_target`. Никакого парсинга имён строкой.
- Мёртвое поле `class` объекта из barnes-features S8 получает семантику = `zone_class`.
- **Центр арены** = центроид маски арены (авто, вычисляется на этапе определения масок),
  **с возможностью ручного сдвига**, хранится в пресете. UI-сдвиг -> S4.
- `angle` зоны вычисляется из её центроида относительно центра арены. Нужен для угловых
  Barnes-метрик.
- Обратная совместимость: пресеты S1 без ролей читаются с `zone_class` по эвристике
  (или "arena"/"object" по старому `type`), `is_target=False`, `angle=None`. Отсутствие
  роли там, где парадигма её требует, -> варнинг валидации (слой 7), не тихий дефолт.

### Слой 2. Селекторы зон и композиты

`select(zones, predicate) -> CompositeZone` (union масок отобранных зон). Предикаты —
по `zone_class` / `is_target` / `tags` / `index`:

```
target_hole   = select(class=="hole" and is_target)      # 1 зона
neutral_holes = select(class=="hole" and not is_target)   # union
all_holes     = select(class=="hole")                     # union
```

Одиночные зоны сохраняются; композиты живут рядом. Их состав объявляет парадигма (слой 6).
`CompositeZone` — та же структура Zone с `zone_class="composite"` и списком членов.

### Слой 3. Привязка акта (никогда к конкретному имени зоны)

Акт привязывается к одному из четырёх:

| Привязка | Даёт | Пример |
|---|---|---|
| одна зона | обычный zone-акт | `in_center` |
| класс зон (семейство) | N актов + слитый `EventStream` | `nose_at_hole[k]` |
| композит | один сигнал по union | `nose_at_any_neutral_hole` |
| роль-селектор | член семейства по роли | `nose_at_target = where(is_target)` |

**Правило, распутывающее всё:** акты и метрики НЕ имеют права называть конкретную зону —
только класс, композит или роль-селектор. Роли задаются один раз в геометрии и наследуются
вниз при разворачивании семейства. Следствия: `nose_at_target` — селектор, не отдельное
определение; `order_barnes` — generic-метрика над слитым EventStream; `NumObjects=19`-хардкод
исчезает (семейство разворачивается по фактическим зонам класса).

### Слой 4. Модель акта v2

Расширение S1 `Act`/`ActContext`/`apply_act`.

**(a) Части тела и деградация (решение 1).**
```
Act.required_parts: list[str]           # роли/части, нужные акту
Act.fallback: dict[str, list[str]]      # part -> упорядоченная цепочка замен
```
Резолвер: для каждой требуемой части берёт первую доступную (не NotFound) из
`[part] + fallback[part]`. Если ни одна недоступна -> варнинг + результат акта = честный
NaN-маска (все кадры NaN/false) + `Act`-результат помечается `degraded=True` с причиной.
Никогда не подставляет «похожую» часть молча. Библиотека стандартных цепочек
(`bodyparts/fallbacks.py`) — источник дефолтов, которые акт может взять или переопределить.

**(b) Composition — AST (решение 2).**
```
ActExpr = Leaf(act_ref | zone_pred | speed_gate | special)
        | Or(children)  | And(children)  | Exclude(base, subtract)
        | Sequence(steps, delays_sec)
```
Evaluator (`acts/expr.py`) обходит дерево -> per-frame bool-маска:
- `Or`/`And` — поэлементные union/intersection масок детей;
- `Exclude(base, subtract)` — `base & ~subtract` (покрывает «обследование носом ЗА
  ВЫЧЕТОМ времени в объекте»);
- `Sequence(steps, delays)` — событие, когда шаги активируются по порядку с допуском
  задержки между ними (обобщает `seq_delay_sec` S1);
- `Leaf` с `act_ref` — ссылка на другой именованный акт (reuse); вычисляется через DAG
  (топологический порядок, реестр `resultsByName`).
Плоская S1-модель (`components`+`operation`+`seq_delay_sec`) мигрируется в эквивалентные
AST (`OR`/`EXCLUDE`/`Sequence`); старые библиотеки актов читаются и конвертируются.

**(c) Post-filters** в схеме акта: median-window (сглаживание маски) + min-duration
(отсев коротких эпизодов). Уже частично в S1 refine; выносятся в декларативные поля акта.

**(d) FreezingMode / RearMode** становятся свойствами акта в библиотеке, НЕ параметрами
анализа (config.acts.*). Встроенные freezing/rear переописываются как библиотечные акты с
этими свойствами; `analyze_session` перестаёт хардкодить режимы.

### Слой 5. Реестр именованных метрик

- **Авто `акт×стат`** — НЕ регистрируются, порождаются на каждый акт (S1 `act_stats`).
- **Именованные** — декоратор `@register_metric` с ЯВНЫМИ зависимостями:
  ```
  @register_metric(name, requires_acts=[...], requires_events=[...],
                   requires_geometry=[...], paradigm=[...])
  def metric(ctx) -> float | dict: ...
  ```
  Явные deps дают: порядок вычисления (топологически), внятную ошибку вместо тихого NaN
  при отсутствии зависимости, фильтрацию под парадигму в GUI.
- `ratio_index(act_a, act_b) = (A - B) / (A + B)` — параметризованная, между ЛЮБЫМИ двумя
  актами, конфигурируется в конструкторе. NOR-дискриминация = частный случай. Хардкода
  `nose_novel/nose_familiar` нет.
- Universal act-derived над Events (из TODO): `time_to_completion`,
  `time_to_first_completion`, `visit_order`, `primary_errors =
  count_distinct_labels_before(first event where is_target)`.

### Слой 6. Иерархия парадигм (декларативный бандл + наследование)

```
Paradigm:
  name: str
  parent: Paradigm | None            # наследование
  required_zone_roles: [...]         # что должно быть размечено
  composites: [CompositeSpec]        # какие композиты собрать
  acts: [ActSpec]                    # библиотека актов парадигмы
  metrics: [MetricRef]               # какие именованные метрики включить
  config_defaults: dict              # per-experiment дефолты (пороги и т.п.)
  validation: [Rule]                 # правила применимости (слой 7)
```

Иерархия:
```
OF   (пустое поле любой формы, объектов нет)
 |    акты: пространственные (если зоны) + скоростные + фризинг + стойки
 |    метрики: дистанция, средняя скорость, посещаемость арены
 +-> EOF (enriched, >=1 объект) — НАСЛЕДУЕТ всё из OF
 |     + объектные акты: обследование носом в кольце (EXCLUDE время в объекте),
 |                       животное в объекте (центр внутри)
 |     + метрики: ratio_index между выбранными объектами
 |     +-> NOR = EOF ровно с 2 объектами
 +-> Barnes    (свои метрики — слой 8)
 +-> T/Y-maze  (метрики выбора/решения — ОТЛОЖЕНЫ, каркас парадигмы есть)
 +-> New       (пользовательская: геометрия/объекты/акты/метрики; save/load JSON)
```
Наследование склеивает роли+акты+метрики+дефолты родителя с добавками потомка (потомок
переопределяет одноимённое). Парадигма — данные, не набор `if` в коде.
S1 `open_field()` (минимальный бандл) заменяется полноценным OF этого слоя.

### Слой 7. Валидация как данные (§10)

Правила применимости — данные, не исключения в коде:
- EOF требует >=1 объект;
- NOR требует ровно 2 объекта;
- Barnes требует ровно одну зону с `is_target`;
- задан pxl2sm (иначе дистанции/скорости невалидны).

`validate(paradigm, preset) -> ValidationReport` — список `{level, code, message, where}`.
Движок ОТДАЁТ структуру; GUI её рендерит (S4). Нарушение -> внятный варнинг пользователю,
НИКОГДА тихий неверный ответ. Сюда же — варнинги на непройденные этапы (нет масок, нет
центра арены, деградировавшие акты из слоя 4a).

### Слой 8. Barnes-метрики

Считаются из слоя Events (семейства `nose_at_hole` / `mouse_inside_hole`) + геометрии
(`is_target`, `angle`). Источник списка: `docs/TODO.md` (Barnes maze — 8 training-day +
9 test-day) и out-of-scope-хвост barnes-features. Набор:
primary/total latency, primary/total errors, path length, angular distance первой/всех
проверенных лунок, ordinal index цели, search-strategy classification (Pitts 2018),
time near target. Каждая — именованная метрика (слой 5) с deps на семейство + геометрию;
включается парадигмой Barnes. Отсутствие данных -> явная ошибка/варнинг, не тихий 0.

## 6. Критерии готовности S2

- OF/EOF/NOR/Barnes собираются как декларативные парадигмы; акты и метрики нигде не
  называют конкретную зону по имени.
- Комплексный акт «обследование носом EXCLUDE время в объекте» выражается AST без спецкода.
- Пропажа части тела -> варнинг + NaN + `degraded`, не тихая подмена (регресс-тест на R31#4).
- `ratio_index(a,b)` работает между любыми двумя актами; NOR-дискриминация — его вызов.
- `validate()` ловит EOF-без-объекта / NOR!=2 / Barnes-без-target и отдаёт отчёт.
- Barnes-метрики считаются из Events+геометрии на демо-Barnes-сессии.
- Полный набор тестов зелёный; whole-branch review на каждой границе милстоуна чист.
