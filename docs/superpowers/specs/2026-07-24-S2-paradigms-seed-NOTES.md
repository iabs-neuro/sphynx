## 1. Корневая проблема (согласовано)

Акты и метрики не «перемешаны» -- это разные уровни (сигнал vs скаляр на сессию).
Настоящая причина каши в Barnes: (а) нет слоя Events, (б) роли зон и наследование
их в акты нигде не выражены -> в MATLAB получились семейства + захардкоженный
`order_barnes`, `NumObjects=19` и т.п.

## 2. Механизм распутывания зоны -> акты (согласовано, «берём»)

**Три уровня, все декларативные:**

**A. Роли живут в геометрии -- единственный источник правды.**
```
Zone: name, mask, zone_class, roles{is_target: bool, tags: [...]}, index, angle
      zone_class = "hole" | "object" | "wall" | "corner" | "arena"
```
Целевая лунка помечается `is_target=True` один раз при рисовании масок. Нейтральные --
это `zone_class=="hole"` без `is_target`. Никакого парсинга имён строкой.
(Приятно: мёртвое поле `class` объекта из barnes-features S8 наконец получает
семантику -- это `zone_class`.)

**B. Композитные зоны -- производные, рождаются селектором по ролям** (идея юзера):
```
target_hole   = select(class=="hole" and is_target)      -> 1 зона
neutral_holes = select(class=="hole" and not is_target)  -> union масок
all_holes     = select(class=="hole")                    -> union масок
```
Одиночные зоны остаются все; композиты живут рядом; их состав объявляет парадигма.

**C. Акт привязывается к одному из четырёх, НИКОГДА к конкретному имени зоны:**

| Привязка | Даёт | Пример |
|---|---|---|
| одна зона | обычный zone-акт | `in_center` |
| класс зон (семейство) | N актов + слитый `EventStream` | `nose_at_hole[k]` |
| композит | один сигнал по объединению | `nose_at_any_neutral_hole` |
| роль-селектор | член семейства по роли | `nose_at_target` = `where(is_target)` |

**Правило, которое всё распутывает:** акты и метрики не имеют права называть
конкретную зону -- только класс, композит или роль-селектор. Роли задаются один раз
в геометрии и наследуются вниз при разворачивании семейства.

### Что от этого разваливается (в хорошем смысле)
- `nose_at_target` -- не отдельное определение, а селектор `where(is_target)` над семейством.
- `order_barnes` -- generic-метрика `visit_order` над слитым `EventStream` любого семейства. Barnes просто включает.
- `primary_errors` = `count_distinct_labels_before(first_event where is_target)` -- generic-запрос над Events.
- `NumObjects=19`-хардкод исчезает: семейство разворачивается по фактическим зонам класса.

## 3. Композитные акты через зоны (согласовано)

«Обследование носом ЗА ВЫЧЕТОМ времени внутри объекта» = композитный акт через
вычитание зон (`nose_in_ring EXCLUDE center_in_object`). Механизм из §2 покрывает
без спецкода. Это же -- вход в редизайн комплексных актов (expression composition
из TODO): `Act1 OR Act2 EXCLUDE Act3`, последовательности с задержками.

## 4. Центр арены и угол (согласовано)

- Центр арены -- **авто** (центроид маски арены) на этапе определения масок,
  **с возможностью подвинуть вручную**, хранится в пресете.
- `angle` зоны = угол её центроида относительно центра арены. Нужен для угловых
  Barnes-метрик (angular distance первой/всех проверенных лунок).
- UI-сдвиг центра -> S4.

## 5. Иерархия парадигм (согласовано, структура юзера)

```
OF   (пустое поле любой формы, объектов нет)
 |    акты: пространственные (если зоны) + скоростные + фризинг + стойки
 |    метрики: дистанция, средняя скорость, посещаемость арены
 +-> EOF (enriched, >=1 объект) -- НАСЛЕДУЕТ все акты и метрики OF
 |     + объектные акты: обследование носом в кольце (ЗА ВЫЧЕТОМ времени в объекте),
 |                       нахождение животного в объекте (центр внутри)
 |     + метрики: дискриминация между выбранными объектами
 |     +-> NOR = EOF ровно с 2 объектами
 +-> Barnes    (свои метрики -- см. §8)
 +-> T/Y-maze  (выбор/решение, доп. метрики -- ОБСУДИТЬ ПОЗЖЕ)
 +-> New       (пользовательская: геометрия арены, кол-во объектов, акты, метрики;
                создаётся и сохраняется/грузится)
```
Парадигма = декларативный бандл (роли зон + акты + метрики), с наследованием, а не
набор `if` в коде.

## 6. Валидация парадигм как данные (согласовано; политика §10 S1)

Правила применимости, например:
- EOF требует >=1 объект;
- NOR требует ровно 2 объекта;
- Barnes требует ровно одну зону с `is_target`.
Нарушение -> **внятный варнинг пользователю** (движок отдаёт структуру валидации,
GUI её рендерит). Никаких тихих неверных ответов. Сюда же -- варнинги на непройденные
этапы (например не определён пиксель-на-см).

## 7. Реестр метрик (согласовано)

- Автогенерируемые `акт x стат` -- НЕ регистрируются, порождаются для каждого акта.
- Именованные -- `@register_metric` с **явными зависимостями** (`requires_acts` /
  `requires_events` / `requires_geometry` / `paradigm`). Дают порядок вычисления,
  внятную ошибку вместо тихого NaN, фильтрацию под парадигму в GUI.
- `ratio_index(act_a, act_b) = (A-B)/(A+B)` -- параметризованная, между ЛЮБЫМИ двумя
  актами, конфигурируется в конструкторе. NOR-дискриминация -- частный случай.
  Хардкода `nose_novel/nose_familiar` нет.
- Universal act-derived (из TODO): `time_to_completion`, `time_to_first_completion`
  -- именованные метрики над Events.

## 8. Barnes-метрики (переехали сюда из S1)

Считаются из слоя Events (семейство `nose_at_hole` / `mouse_inside_hole`) + геометрии
(is_target, angle). Источник списка: `docs/TODO.md` (Barnes maze metrics -- 8
training-day + 9 test-day) и out-of-scope-хвост `barnes-features` спеки.
Примеры: primary/total latency, primary/total errors, path length, angular distance
первой/всех лунок, ordinal index цели, search-strategy classification (Pitts 2018),
time near target.
