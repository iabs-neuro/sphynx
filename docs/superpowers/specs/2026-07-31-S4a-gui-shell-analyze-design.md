## 1. Декомпозиция S4

Порт MATLAB-GUI — это ~10k строк в шести живых вкладках (CreatePreset 3.7k, Preprocess
2.4k, DefineActs 1.6k, Analyze 1.3k, Batch 1.0k, MakeOutput 0.7k). За одну спеку не влезет,
поэтому S4 режется на пять срезов; каждый получает свою спеку -> план -> реализацию.

**Окно с шестью вкладками существует с первого среза.** Ненаполненные вкладки показывают
заглушку «будет в срезе N» — навигация ощущается целиком с самого начала.

| Срез | Содержание |
|---|---|
| **S4a** (эта спека) | Каркас окна, `AppState`, вкладка **Analyze Session**, **мост движка к S2** |
| S4b | **DefineActs** — двухпанельный конструктор актов/метрик; **этограмма** |
| S4c | **Batch + MakeOutput**, project/метаданные |
| S4d | **CreatePreset** — рисование зон, роли, калибровка, центр арены |
| S4e | **Preprocess Tracking** |

Порядок выбран по пути данных: Analyze работает на демо-сессии уже сегодня, поэтому первый
же срез запускается на реальных данных пользователя.

**Вне S4** (свои будущие спеки): Plot Data (стат-тесты), Preprocess Video, Synthetic Data.

**Честное ограничение S4a:** видео-рендер (`renderActsVideo` / `renderActStitched`) в Python
не портирован, поэтому кнопок Render в этом срезе нет. Появятся тогда, когда будет порт.

## 2. Мост движка к S2

Сегодня `analyze_session` считает только встроенные акты S1 и ничего не знает о парадигмах,
семействах и метриках. Это задокументированная граница S2->S4, и снимается она здесь.

```
analyze_session(config, paradigm=None) -> SessionResult
```

`paradigm` — имя или объект `Paradigm`. Когда задан:

1. `resolve_paradigm` (наследование) -> `validate_paradigm(paradigm, zones, options)`;
   отчёт кладётся в результат **до** расчёта. Нарушение правил НЕ останавливает анализ —
   пользователь видит и цифры, и почему им нельзя верить.
2. Строятся композиты парадигмы (`make_composite`) и добавляются к списку зон.
3. Семейства разворачиваются по фактическим зонам (`expand_family`), конкретные акты
   вычисляются через `eval_acts_library` и добавляются к `result.acts`.
4. Собираются `EventStream` семейств (`family_event_stream`).
5. Метрики парадигмы считаются через `compute_metric_refs` с `lineage(paradigm)`, чтобы
   парадигма-наследник получала метрики родителя.

`SessionResult` получает поля: `validation` (ValidationReport | None), `metrics`
(MetricResults | None), `event_streams` (dict), `degraded` (dict из ActContext).

**Приоритет настроек:** `Options` пресета > `config_defaults` парадигмы > `Config`.
Парадигма даёт разумные умолчания, реальный пресет их перебивает.

**Ошибки:** отсутствие парадигмы с таким именем -> `SphynxValueError` (как везде в S2).
Ошибки отдельных метрик собираются в `MetricResults.errors`, не роняя анализ.

## 3. Архитектура приложения

- **PySide6**. Пакет `src/sphynx_gui/`, отдельный от движка: `sphynx` не должен зависеть
  от Qt (движок обязан оставаться пригодным для CLI и headless-батчей).
- **`AppState`** — единый объект состояния окна: пути (DLC, пресет, выходная папка),
  выбранная парадигма, `Config`, последний `SessionResult`. Испускает Qt-сигналы при
  изменениях; вкладки подписываются, а не хранят копии. Это решает пункт TODO
  «app-wide state»: в MATLAB каждая вкладка грузила пути заново.
- **Виджеты не содержат логики движка.** Контроллер вкладки собирает `Config` из
  `AppState`, вызывает движок и раскладывает результат по виджетам. Границы: виджет знает
  только про свои поля, контроллер — только про движок и `AppState`.
- **Анализ в рабочем потоке** (`QThread` + worker-объект). Окно не морозится, есть прогресс
  и отмена; полная сессия на 18k кадров считается секунды. Исключения движка перехватываются
  в воркере и доезжают до UI как сообщение об ошибке, а не как падение приложения.
- **Графики — matplotlib, встроенный в Qt** (`FigureCanvasQTAgg`), переиспользуя
  `sphynx.plot`. Вторая графическая библиотека не вводится (YAGNI).
- Сохранение/загрузка настроек — один TOML через существующий `Config.to_toml/from_toml`
  плюс пути и парадигма.

## 4. Вкладка Analyze Session

**Слева** узкая колонка:
- пути: DLC csv, пресет .mat, выходная папка (кнопки выбора + видимый текущий путь);
- выпадающий список парадигм (из реестра встроенных);
- ключевые настройки: bin хитмапа (см), диапазон кадров (start/end);
- кнопка **Run** (во время расчёта — прогресс и отмена);
- панель варнингов (см. §5).

**Справа** — сетка 2x2 графиков: траектория, хитмап занятости, гистограмма скорости,
скорость по времени. Двойной клик по графику разворачивает его на всю область и обратно,
так что детали доступны без смены режима. Этограмма добавляется в S4b.

**Под графиками** две таблицы:
- акты: имя, %, число эпизодов, длительность (с), дистанция (см), средняя скорость;
- метрики парадигмы: имя -> значение. Метрики, которые посчитать не удалось, показываются
  с текстом ошибки, а не пустой клеткой: «не смогли и почему» — это результат, а не пустота.

## 5. Поверхность варнингов

Одна панель собирает три источника и помечает каждый источник:
1. отчёт валидации парадигмы (ошибки и предупреждения, с кодом и сообщением);
2. деградировавшие акты (`SessionResult.degraded`) — что подставлено или не найдено;
3. ошибки метрик (`MetricResults.errors`).

Это первая витрина политики §10: видно глазами, где движок отказался угадывать. Пустая
панель — значимый сигнал, а не отсутствие информации.

## 6. Тестирование

- `pytest-qt`, headless (`QT_QPA_PLATFORM=offscreen`), чтобы GUI-тесты шли в общей сюите.
- Покрывается: `AppState` и его сигналы; контроллер (сборка `Config`, раскладка результата,
  обработка ошибки движка); воркер-поток (успех, исключение, отмена); наполнение таблиц и
  панели варнингов из результата.
- Мост движка тестируется как обычный движковый код, включая прогон на демо-сессии
  `Demo/NOF_H01_1D` с парадигмой OF.
- Пиксели отрисовки не тестируются.

## 7. Критерии готовности S4a

- Приложение запускается одной командой, показывает шесть вкладок; пять из них — заглушки.
- На демо-сессии `NOF_H01_1D` с парадигмой OF: Run отрабатывает в фоне, появляются четыре
  графика, таблица актов и метрик, панель варнингов.
- Выбор парадигмы, требующей объектов (EOF/NOR), на этом же пресете даёт видимое
  предупреждение валидации вместо тихо неверных цифр.
- `analyze_session` с парадигмой считает её семейства и метрики; без парадигмы ведёт себя
  ровно как раньше (обратная совместимость).
- Полная сюита зелёная.
