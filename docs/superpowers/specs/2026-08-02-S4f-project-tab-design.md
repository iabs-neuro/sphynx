## 1. Место в порядке работ

Повышено в приоритете решением пользователя 2026-08-02: **до** доделки Create Preset.
Причина простая — пока проекта нет как первого класса, каждая вкладка спрашивает пути
заново, и доделывать Create Preset пришлось бы дважды.

Движок проекта готов с S4c (`sphynx/project/`: модель, `save_project`/`load_project`,
скан папки, правила пресетов), но живёт целиком внутри вкладки Batch, а `AppState` держит
`dlc_path`/`preset_path`/`out_dir`/`paradigm` отдельно от проекта. Ни Analyze, ни Create
Preset из проекта не читают ничего.

**Входит:** проект как папка с фиксированной раскладкой; создание, открытие, сохранение;
относительные пути внутри и явно помеченные внешние; добавление видео и трекинга
копированием или ссылкой; проект как единственный источник парадигмы, библиотеки актов и
папок; новая вкладка Project первой; перестановка вкладок; миграция схемы v1 → v2.

**Не входит:** мостики к Bonsai и SLEAP (папка `tracking/` названа так на вырост, читаем
пока только DLC); предварительный анализ сессии внутри Define Acts; перенос сканирования
и правил пресетов из Batch.

## 2. Проект — это папка

Создание проекта делает раскладку целиком:

```
<ProjectRoot>/
  project.json
  raw_videos/          видео сессий
  tracking/            трекинг; сейчас DLC csv, на вырост Bonsai/SLEAP
  presets/             пресеты, которые строит Create Preset
  behavior/            результаты пакетного прогона по сессиям + графики
  temp/                настроечные одиночные прогоны Analyze Session
  acts_library.json    библиотека актов проекта
  preprocess.json      настройки препроцессинга проекта
  <итоговая таблица>   то, что пишет Make Output
```

Пустые подпапки создаются сразу, а не при первой записи: пользователь должен видеть, куда
складывать файлы руками — это третий из названных способов наполнения, наравне с
копированием и ссылкой.

Открытие проекта — выбор `project.json` **или** самой папки; во втором случае ищется
`project.json` внутри. Отсутствие подпапки не ошибка: она достраивается, и об этом
сообщается — проект мог приехать без пустых папок.

## 3. Пути

Хранение в `project.json` по одному правилу: **под корнем — относительный путь, вне корня
— абсолютный**. Различить их можно по самому значению (`os.path.isabs`), отдельного флага
нет — флаг мог бы разойтись со строкой.

```python
def store_path(path, root) -> str      # относительный, если под корнем; иначе абсолютный
def resolve_path(stored, root) -> str  # обратно, всегда абсолютный
def is_external(stored) -> bool        # то же, что isabs
```

Настоящие символические ссылки не используются: на Windows `os.symlink` на файл требует
прав администратора либо Developer Mode, жёсткие ссылки не пересекают том, а `.lnk`
Проводника Python не разыменует. Обещать «ярлык» уровня ОС было бы обещанием, которое
сломается на машине пользователя.

**Добавление видео или трекинга извне** спрашивает одно: скопировать в проект или оставить
на месте. Копирование кладёт файл в `raw_videos/` или `tracking/` и пишет относительный
путь. Ссылка пишет абсолютный, и строка в таблице сессий получает пометку **«вне
проекта»**. Пометка обязательна: без неё проект, который не переедет целиком, выглядит как
переносимый.

Файл, положенный пользователем в подпапку руками, ничем не отличается от скопированного —
скан находит оба одинаково.

## 4. Проект — источник истины

Сегодня одно и то же значение живёт в двух местах: `AppState.paradigm` и `Project.paradigm`,
`AppState.out_dir` и `Project.out_dir`. Расхождение между ними ничем не видно, и какое из
них уйдёт в анализ, зависит от того, какая вкладка его запустила.

После среза владельцем становится проект. `AppState` перестаёт хранить эти значения
самостоятельно и проксирует их в `Project`, оставляя сигналы прежними, чтобы вкладки не
переписывались:

| значение | было | станет |
|---|---|---|
| `paradigm` | поле `AppState` | `project.paradigm` |
| `out_dir` | поле `AppState` | зависит от того, кто пишет: Batch и Make Output — `behavior/` и корень, Analyze Session — `temp/` |
| `library` | поле `AppState` | читается из `project.library_path` |
| `dlc_path`, `preset_path` | поля `AppState` | **остаются** — это выбор текущей сессии, а не настройка проекта |

Правка в любой вкладке меняет проект и помечает его несохранённым. Несохранённость видна
на вкладке Project и в заголовке окна; закрытие с несохранёнными изменениями спрашивает.

## 5. Вкладка Project

Первая в окне. Слева — что за проект, справа — что в нём лежит.

- **Проект**: New (выбор папки → раскладка создаётся), Open, Save, Save As; имя; корень;
  пометка «есть несохранённые изменения».
- **Папки**: пять строк — `raw_videos`, `tracking`, `presets`, `behavior`, `temp` — с путём
  и состоянием (есть / создана только что / недоступна). Переопределение папки допускается,
  и тогда путь показывается как заданный вручную.
- **Настройки проекта**: парадигма (список из реестра S2), библиотека актов (путь +
  «создать пустую в корне»), папка результатов.
- **Добавить данные**: «Добавить видео…» и «Добавить трекинг…» — множественный выбор
  файлов, затем один вопрос «скопировать в проект или оставить на месте».
- **Состояние**: сколько сессий, сколько из них с неразрешимыми путями, сколько внешних.
  Та же панель варнингов, что в остальных вкладках.

## 6. Что меняется в других вкладках

Порядок вкладок (решение пользователя): **Project, Create Preset, Preprocess, Define Acts,
Analyze Session, Batch Analysis, Make Output**.

- **Batch** теряет кнопки New/Open/Save project — они переехали. Таблица сессий, скан,
  правила пресетов, прогон и результаты остаются как есть.
- **Create Preset** открывает диалог видео в `raw_videos/` и сохраняет пресет по умолчанию
  в `presets/`.
- **Analyze Session** открывает выбор DLC в `tracking/`, пресета — в `presets/`, пишет в
  **`temp/`**. Одиночный прогон здесь — это настройка: подобрать пресет, парадигму и акты
  на одной сессии, а считать по-настоящему будет Batch, и он же перепосчитает эту сессию
  в `behavior/`. Складывать настроечные прогоны рядом с итоговыми — верный способ потом
  не понять, какие числа настоящие. `temp/` никогда не читается ни Batch, ни Make Output,
  и **не чистится сама**: удалять чужие файлы молча приложение не будет.
- **Make Output** пишет итоговую таблицу в корень проекта.
- Без открытого проекта вкладки работают как сейчас: диалоги стартуют где придётся, всё
  задаётся руками. Проект — удобство и единый источник, а не обязательное условие.

## 7. Миграция схемы

`project.json` переходит на `schema_version = 2`. Новые поля: `root` (для справки; при
чтении корень всё равно берётся от расположения файла, чтобы переехавший проект работал),
`raw_videos_dir`, `tracking_dir`, `presets_dir`, `behavior_dir`, `temp_dir`,
`preprocess_path`. `ProjectSession` получает `video_path`.

Файл версии 1 читается и повышается: корнем становится папка, где лежит `project.json`,
все существующие пути остаются абсолютными, то есть честно превращаются во «внешние» —
именно тем, чем они и были. Повышение не пишется на диск само; проект помечается
несохранённым, и пользователь сохраняет его сам. Молча переписать чужой файл при открытии
было бы ровно тем тихим действием, которое запрещает §10.

## 8. Тестирование

- **Движок**: `store_path`/`resolve_path` — круговой проход для пути под корнем и вне его;
  `is_external`; создание раскладки идемпотентно; копирование кладёт файл в нужную подпапку
  и возвращает относительный путь; отсутствующий источник — ошибка, а не пустой файл;
  чтение v1 повышает и помечает несохранённым; чтение v3 — ошибка с названной версией;
  неизвестное поле — ошибка (как сейчас).
- **GUI (headless)**: New создаёт пять подпапок и `project.json`; Open заполняет поля;
  правка парадигмы во вкладке Analyze меняет `project.paradigm` и помечает несохранённым;
  добавление внешнего файла со ссылкой даёт строку с пометкой «вне проекта», с копированием
  — файл в подпапке и относительный путь; закрытие с несохранёнными спрашивает.
- **Интеграционный**: создать проект во временной папке, положить в него демо-DLC и
  демо-пресет, прогнать пачку, переименовать папку проекта целиком и открыть снова.

**Поправка по факту реализации.** Проверить, что файлы результатов оказываются в
`behavior/`, оказалось нечем: `config.io.save_workspace` и `config.paths.out_dir`
протаскиваются через движок и нигде не читаются — шаг 12 `analyzeSession.m`
(`sphynx.io.saveSession`) не портирован, см. раздел B2 инвентаризации. Папки заведены
правильно, писателя у них нет. Тест проверяет, **куда нацелен** каждый прогон
(`batch_out_dir` → `behavior/`, одиночный → `temp/`), а не какие файлы появились.

## 9. Критерии готовности

- Новый проект создаётся одной кнопкой и сразу имеет раскладку.
- Открыв проект, можно пройти по вкладкам слева направо, ни разу не указав папку руками.
- Проект, целиком лежащий под своим корнем, переносится на другую машину и открывается;
  проект со ссылками наружу открывается и **показывает**, какие строки не переехали.
- Парадигма и библиотека имеют ровно одно значение на приложение.
- Полная сюита зелёная.
