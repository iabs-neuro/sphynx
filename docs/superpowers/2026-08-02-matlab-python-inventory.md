# Инвентаризация MATLAB → Python

Дата: 2026-08-02
Ветка: `Sphynx-python`, сюита 933.
Повод: расхождения вкладки Create Preset с MATLAB, которых не было ни в одной спеке
(см. разбор в переписке 2026-08-02). Спеки писались от списка модулей, которые я выбирал
портировать, а не от инвентаря MATLAB-приложения, поэтому потери были невидимы.

## Как это собрано и чему верить

Два прохода:

1. **Машинный** — `MATLAB .m` → кандидат `snake_case` → поиск `def`/`class` и упоминания
   имени в `src/`. 121 файл, 63 без следа. **Этот сигнал грубый**: несколько .m свёрнуты в
   одну Python-функцию (`buildZonesCircleWall`/`Center` живут внутри `classify_circle`), а
   `barnesSessionMetrics` лежит в `metrics/barnes.py` под другим именем. Числа из машинного
   прохода — только для приоритизации.
2. **Ручной** — вкладка Create Preset разобрана по кнопкам и панелям самого
   `CreatePresetApp.m` (3693 строки). Раздел A ниже проверен глазами; разделам B и C верить
   как оценке, каждый пункт требует отдельной проверки перед планированием.

Легенда: **есть** — работает в Python; **иначе** — сделано другим механизмом сознательно;
**нет** — отсутствует; **нет (спека)** — отсутствует и было заявлено в «не входит».

### A5. Zones — производные зоны

**Главное расхождение среза.** MATLAB даёт выпадающий список из шести стратегий, и
пользователь выбирает её явно. Python стратегии не выбирает вовсе: она выводится из формы
нарисованной арены (эллипс → `classify_circle`, прямоугольник → `classify_square`).
Две стратегии при этом отсутствуют в Python как таковые, включая **дефолтную**.

| стратегия MATLAB | что строит | Python |
|---|---|---|
| `circle` (**дефолт приложения**) | `buildZonesCircleWall`: кольцо стены + центр = всё остальное. Работает на **любой** форме арены | **нет** |
| `circle-rings` | `buildZonesCircle` → `classifyCircle`: стена + middle1..N + центр | **есть**, `classify_circle` — и Python выдаёт именно это на любой эллиптической арене |
| `circle-with-center` | `buildZonesCircleCenter`: стена + концентрический диск диаметра `CenterDiameterCm` | **нет** |
| `corners-walls-center` | `classifySquare` | **есть** |
| `strips` | `partitionStrips` | **частично**: движок портирован, GUI не предлагает |
| `none` | только арена | **есть** |

То есть на круглой арене Barnes MATLAB по умолчанию даёт 2 зоны (стена + центр), а Python
молча даёт стену + N средних колец + центр. Наборы зон разные, и это не отмечено нигде.

| прочее | Python | Комментарий |
|---|---|---|
| Corner type round / square | **частично** | `square` в порту явно не реализован и даёт ошибку |
| Wall, cm | **есть** | одно поле на прямоугольник и эллипс |
| Middle, cm | **нет** | `classify_circle` принимает `middle_width_cm`, GUI не отдаёт |
| Center diameter, cm | **нет** | относится к `circle-with-center`, которой нет |
| `MinCenterCm` | **сверено** | в MATLAB тоже ни на что не влияет (комментарий в `classifyCircle.m:89` устарел, цикл его не читает); порт точен |
| Obj zone width, cm | **есть** | кольцо 2.5 см |
| Preview zones | **нет** | сейчас: построить и увидеть счётчик по классам |
| Clear zones | **нет** | |
| Кольцо в нормализованном пространстве при `x_kcorr != 1` | **есть** | и теперь наконец получает измеренный `x_kcorr` |

## D. Что это значит для порядка работ

1. **Вкладка Project первой** (решение пользователя 2026-08-02): создание, загрузка и
   настройка проекта; остальные вкладки берут пути и настройки оттуда. Движок готов
   (`sphynx/project/`: модель, `save/load_project`, скан, правила пресетов), но живёт
   целиком внутри Batch, отдельной вкладки нет, и ни Analyze, ни Create Preset из проекта
   ничего не читают. Закрывает строки «Project root» и «Out dir» из A1.
2. **Create Preset до конца.** По разделу A остаток крупными кусками, в порядке
   убывания последствий:
   - **явный выбор стратегии зон** (A5) плюс две недостающие — `circle` и
     `circle-with-center`. Сейчас круглая арена молча получает не тот набор зон, что в
     MATLAB, и это влияет на числа, а не только на удобство;
   - авто-детект объектов (A4) — самая большая одиночная потеря, 151 строка;
   - copy xN + Order Barnes (A4) — без них Barnes размечается вручную;
   - загрузка и правка существующего пресета (A1);
   - производные зоны полигональной арены (A3);
   - надёжность видео: `correctedFrameCount` + fps только для чтения (A1).
3. **fps** — отдельная заметка: MATLAB берёт частоту из `VideoReader` и пользователю её не
   отдаёт; в Python это редактируемое поле с дефолтом 30. Правильная форма — поле только
   для чтения, редактирование открывается лишь когда чтение провалилось, с пометкой в
   Options, что значение введено руками.
4. **Разделы B и C** — по каждому пункту нужна отдельная проверка, прежде чем ставить в
   план. Сейчас это список подозрений, а не список задач.
